# 养号循环设计（修订版）

> 依据本轮决策重规划：
> 1. **不做「关注」**（无接口，直接砍掉）
> 2. **「刷 feed」做真滚动**（见 §2）
> 3. **评论接 LLM 生成**
> 4. **养号阶段由「小 Web 后台」人工管理**
> 5. **持久化直接用 SQLite**
> 其余沿用：有头(headful)、常驻会话(Session)、路线 B（复用 xiaohongshu 动作层）。

---

## 1. 决策与边界

| 项 | 决定 |
|---|---|
| 载体 | 浏览器（有头），本机 macOS 运行 |
| 底座 | `ref/xiaohongshu-mcp` 的动作层 + humanize + 内置指纹 Chromium |
| 常驻会话 | keeper 内自持 `browser+page`，一场会话只开一次 |
| 关注 | **不做** |
| 刷 feed | **真滚动浏览**（keeper 内实现，见 §2） |
| 评论 | **LLM 生成**（可配置审核） |
| 阶段推进 | **Web 后台人工设置/推进**（系统给建议值） |
| 存储 | **SQLite** |
| 单号/多号 | V1 单号，多号架构预留（一号一 browser+profile+proxy） |

## 2. 「刷 feed」实现说明（核心拟人行为）

**问题**：现成 `list_feeds` 只读 `__INITIAL_STATE__.feed.feeds` 快照——不滚动、不停留、不加载更多，采集可以，养号不行。

**真刷动作**（keeper 内 `browse.go`，直接用 rod 操作页面）——**刷 N 条就刷新，不无限下滑**：
```
刷新首页(reload) → 本轮已看计数 c = 0
loop 直到 浏览时长用完 或 本行为结束:
  随机滚动 1~3 屏（Mouse.Scroll 逐格 100~140px，间隔 20~60ms，走 humanize）
  每屏停留 2~6s（看封面/标题）
  以 ~15% 概率点开一张可见卡片 → 详情(停留/滑评论) → 返回继续
  每消费一张卡片 c++
  if c >= N:                      // N 本轮随机 20~50 条
      刷新首页 reload + humanize.AfterNavigate
      c = 0                        // 新一批推荐
  if 滑到底且懒加载不再新增:
      刷新首页 reload
```
- **为什么刷新**：无限下滑=非人特征；刷一段刷新一次才像真人，也能换一批更"新鲜"的推荐。
- **不整场一直刷**：`browse_feed` 只是行为之一，行为引擎会穿插 看详情/点赞/收藏/评论，不会从头滚到尾。
- 复用 `humanize.Delay` / `smartScroll` 思路；feed 卡片选择器需单独维护（小红书改版会变）。
- 产出：把"看过的候选笔记"喂进 `Session.queue`，供后续 点赞/收藏/评论 消费。
- 参数：`N`（每轮条数）、`browse 时长预算` 走 rhythm 配置，按阶段可调。

## 5. SQLite 数据模型

```sql
-- 账号
CREATE TABLE accounts (
  id TEXT PRIMARY KEY, nickname TEXT, red_id TEXT,
  first_login_at INTEGER, stage INTEGER DEFAULT 0,   -- 0Observe 1Light 2Deepen 3Social 4Creator
  status TEXT DEFAULT 'active',                       -- active/paused/cooldown
  cooldown_until INTEGER DEFAULT 0, risk_score INTEGER DEFAULT 0,
  keywords TEXT,                                      -- 人设兴趣词 JSON
  created_at INTEGER, updated_at INTEGER);

-- 每日配额(按 day 分桶, 跨天自然新行)
CREATE TABLE daily_usage (
  account_id TEXT, day TEXT, used_like INT DEFAULT 0, used_favorite INT DEFAULT 0,
  used_comment INT DEFAULT 0, used_search INT DEFAULT 0, sessions INT DEFAULT 0,
  PRIMARY KEY(account_id, day));

-- 互动审计 + 去重
CREATE TABLE interactions (
  id INTEGER PRIMARY KEY AUTOINCREMENT, account_id TEXT, note_id TEXT,
  author_id TEXT, action TEXT,          -- like/favorite/comment
  note_title TEXT, note_url TEXT, content TEXT, result TEXT,
  created_at INTEGER, UNIQUE(account_id, note_id, action));

-- LLM 评论(生成/审核/发布)
CREATE TABLE comment_jobs (
  id INTEGER PRIMARY KEY AUTOINCREMENT, account_id TEXT, note_id TEXT,
  note_excerpt TEXT, generated TEXT, status TEXT DEFAULT 'pending', -- pending/approved/rejected/posted
  created_at INTEGER, posted_at INTEGER);

-- 风险事件
CREATE TABLE risk_events (
  id INTEGER PRIMARY KEY AUTOINCREMENT, account_id TEXT, type TEXT, -- captcha/ratelimit/login_fail/panic
  detail TEXT, created_at INTEGER);

-- 会话
CREATE TABLE sessions (
  id INTEGER PRIMARY KEY AUTOINCREMENT, account_id TEXT, started_at INT, ended_at INT,
  browse_cnt INT, open_cnt INT, like_cnt INT, fav_cnt INT, comment_cnt INT, outcome TEXT);
```

## 6. 行为引擎

```go
type Stage int // Observe Light Deepen Social Creator(发布,暂不做)

type Behavior interface {
    Key() string
    Weight(st *AccountState) float64 // 0=此阶段不做/配额满
    Run(ctx context.Context, s *Session, st *AccountState) error

```

**行为清单（无关注）**

| Key | 复用 | 拟人要点 | 门槛 |
|---|---|---|---|
| browse_feed | keeper 内滚动(§2) | 每屏停留、偶点开、懒加载 | 全 |
| open_note | NewFeedDetailAction | 按正文/图/视频时长算停留、滑评论 | 全 |
| like | NewLikeAction.Like | 打开→停留→才点；配额+概率 | D3+ |
| favorite | NewFavoriteAction.Favorite | 低概率 | D6+ |
| comment | NewCommentFeedAction + commentgen | LLM 生成/审核后发 | D11+ |
| search_browse | NewSearchAction.Search(kw) | 人设关键词 | D3+ |
| visit_profile | NewUserProfileAction | 主页停留 | D6+ |
| check_notif | NewNotificationAction | 回访 | D11+ |
| rest | sleep | 走神 | 全 |

**阶段权重（默认，人工可在后台改）**

| 阶段 | browse | open | like | fav | comment | search | profile | notif | 日赞 | 日藏 | 日评 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| Observe D1-2 | 70 | 20 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 |
| Light D3-5 | 45 | 25 | 15 | 0 | 0 | 10 | 0 | 0 | 3-8 | 0 | 0 |
| Deepen D6-10 | 35 | 25 | 12 | 8 | 0 | 8 | 5 | 0 | 8-15 | 2-5 | 0 |

## 7. LLM 评论（OpenAI 兼容，默认直接发）

参考 `mengke-wang/xiaohongshu-ai-workbench` 的 `xiaohongshu-comment-reply` 技能的语气/边界原则（像真人、非客服模板、少感叹号、不硬推、不承诺价格效果），但目标改为**给他人笔记发评论**（养号活跃），并加去重与安全校验。

- **接口**：**单一多模态模型**（OpenAI 兼容 `/chat/completions`，支持 `image_url`）。只需配一个模型：`LLM_BASE_URL / LLM_MODEL(多模态) / LLM_API_KEY / LLM_TEMPERATURE(0.85)`。
- **输入两要素**：① 帖子内容（标题+正文摘要+作者/话题 **+ 图片**）② 账号语言风格（persona：如"20岁女生，轻松活泼口语化"）。另加随机**角度**（共情/提问/补经验/夸具体细节/轻微玩笑）避免雷同。
- **看图（方案A：直接把图喂视觉模型）**：
  - 图文：取 `DetailImageList` 前 1~3 张 `URLDefault` → 下载转 base64（下载带 `Referer: https://www.xiaohongshu.com`）→ 作为 `image_url` 拼进同一请求。
  - 视频：取首帧 `VideoDetail.Image.FirstFrameFileID` 拼 CDN（或播放截帧）→ 同上喂。
  - 降级：取图失败 / 正文够长 → 退回纯文本。
  - 请求 `content` = [ text(标题+正文+风格+角度) , image_url × 1~3 ]。
- **默认 direct**：生成即发；`review` 可后台开。发前过**校验闸**，不过则不发。

**Prompt（System）**
```
你是真人小红书用户，正在刷笔记，给这篇笔记留一条自然评论。
铁律：只针对该笔记具体内容说一句，别泛泛而谈；长度 8~40 字、1~2 短句、最多 1 个 emoji；
不提价格/不承诺效果/不涉医疗法律财务/不给也不索要链接或联系方式/不引战不阴阳；
不暴露 AI、不出现"作为…/希望有帮助"等客套；语气贴合【语言风格】，少客服腔、少感叹号。
只输出评论正文，不要解释、不要引号、不要"评论："前缀。
```
**Prompt（User）**
```
【帖子内容】标题：{title} 正文摘要：{desc}  作者/话题：{author_tags}
【语言风格】{persona_style}
【本条角度】{angle}
写这条评论：
```
- **校验闸**：长度 8~40、正则拦 手机号/URL/微信/QQ/价格数字+"元"+敏感词、与历史评论相似度阈值 → 不过则重生成 1 次，仍不过则跳过。
- **发布**：`NewCommentFeedAction.PostComment`（自带"渲染出现"校验防假成功），落 `interactions` 去重。
- **`comment_jobs`**：direct 模式下也记录（status 直接 posted），便于审计/复盘；review 模式为 pending→人工→approved→posted。

## 9. 调度与熔断

- **调度**：keeper 常驻，每 5~10 分钟检查；命中活跃时段(7-9/12-14/19-23)且该号 `active`、`sessions<上限`、非冷却 → 开一场 session（每号一协程、一 browser）。
- **熔断**：每步后 `CheckPageBlocked`；验证页→人工介入+冷却≥24h；登录失效→停+待重登；限流/连续失败→按风险分冷却 2~6h；panic→`safe` 兜住、记 risk_event、必要时重开会话。
